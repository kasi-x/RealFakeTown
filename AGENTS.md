# RealFakeTown — AGENTS.md

## Overview

Real-time guidance puzzle game on real city data: guide a blind grandpa to
the station along braille-block grammar (line = go / dot = decide / warning
= stop) by placing quirky "kindness pieces" that steer his autonomous walk.
The city comes from PLATEAU 3D city models, imported with PLATEAU SDK for
Unity (toon-deformed at render time).

- Full game design doc (Japanese): `docs/game-design.md`
- Map mockup: `docs/concepts/map-mockup.png` (generated by `tools/gen_map_mockup.py`)
- Walkable city graph: `tools/gen_city_graph.py` interprets the Marunouchi
  tran CityGML as a node/edge graph (`make graph`; feeds puzzle-generation
  S1 corridor selection). Render: `docs/concepts/city-graph.{svg,png}`
- Pending design decisions D1–D8 live in the design doc §14 — do not assume
  they are settled.

## Setup

- Unity **6000.3.8f1** via Unity Hub. PLATEAU SDK v4.3.0 declares
  `unity: 6000.3` and is verified upstream on 6000.3.10f1; stay inside the
  6000.3 stream if the editor needs updating.
- The Unity project lives at the **repo root** (`Assets/`, `Packages/`,
  `ProjectSettings/` next to this file).

```bash
make setup     # one-time (and after every version bump): fetches the ~762 MB
               # PLATEAU SDK tarball and the 千代田区 CityGML into vendor/
make verify    # headless resolve + compile check (no GUI); exits non-zero on errors
make graph     # rebuild the walkable graph from CityGML into artifacts/
               # (stdlib-only Python; ~7 s; run `--selftest` for the unit test)
make toolkits  # optional: PLATEAU SDK Toolkits tarball (not wired into the project)
```

Open in Unity Hub → Open → this repo root for normal GUI work. Build/test
commands will be added once the project grows scenes and tests.

## Directory layout

- `docs/` — design documents, `docs/concepts/` mockups + graph render
- `tools/` — dev scripts (map mockup generator, CityGML→graph converter)
- `artifacts/` — **gitignored**: derived data from `make graph`
  (`graph.geojson`, `stats.json`, `city-graph.svg/png`)
- `vendor/` — **gitignored**: big external assets fetched by `make setup`
  — `PLATEAU-SDK-for-Unity-v4.3.0.0.tgz`, `PLATEAU-SDK-Toolkits-*.tgz`
  — `citygml/` — 千代田区 2025 CityGML (`udx/` extracted at `vendor/citygml/`)
- `Assets/`, `Packages/`, `ProjectSettings/` — the Unity project

## Constraints & caveats

- **PLATEAU SDK is installed as a local UPM tarball**: `Packages/manifest.json`
  references `file:../vendor/PLATEAU-SDK-for-Unity-v4.3.0.0.tgz` (relative
  paths resolve against `Packages/`). Never commit `vendor/`, never switch
  the reference to an absolute path. To upgrade the SDK, update the URL and
  file names in the `Makefile` and the manifest reference together.
- **CityGML data is never committed** (GB-scale per city). `make citygml`
  downloads the 千代田区 2025 dataset from the official PLATEAU portal
  resource (URL in the Makefile; dataset page:
  https://www.geospatial.jp/ckan/dataset/plateau-13101-chiyoda-ku-2025)
  and unzips it into `vendor/citygml/`. If the direct download fails it
  falls back to a copy in `~/Downloads`, else prints the dataset page.
  First experiment area is **丸の内: 皇居〜東京駅** — the dataset's DEM meshes are
  `5339-45`/`5339-46` and Marunouchi straddles their boundary, so select the
  5th-mesh tiles in between in the SDK import map.
- **基準座標系 (base coordinate system) must match the imported city**; for
  千代田区 choose **9系 (東京)**. A wrong value silently distorts the model.
- **The city graph (`tools/gen_city_graph.py`) is a v1 topology extract**:
  intersection nodes come from 車道交差部 polygons (merged with a 10 m
  tolerance), street edges from 車道部 polygons with diameter-pair
  centerlines, sidewalks become edge attributes. Lengths/positions are
  approximations — the authoritative network will come from the Unity-side
  import later. `make graph` applies two filters by default:
  **major-road** (`GRAPH_MIN_WIDTH=6.0`: roads whose carriageway area /
  longest strip is under 6 m are pruned — unnamed alleys median ~5.7 m vs
  trunks ≥10 m — plus `--exclude-name 首都高速` for the elevated
  expressway) and **corridor** (`GRAPH_CORRIDOR_BAND=200`: only edges
  within 200 m of the k-shortest 皇居→東京駅 bundle survive; ~88 nodes /
  121 edges / 8 km). `GRAPH_MIN_WIDTH=0 GRAPH_CORRIDOR_BAND=0` regenerates
  the full 51 km graph. **OSM attribute overlay** (`--osm auto`, cached at
  `artifacts/city_graph/osm-cache.json`, `--refresh-osm` to re-download):
  PLATEAU tran has no oneway/crosswalk information, so edges borrow
  `oneway` (+direction) from nearby bearing-aligned OSM ways (one-way
  votes must outweigh two-way votes) and OSM crossing/signals nodes become
  per-edge `crossings` points and per-intersection `crossings` counts.
  The graph stays undirected — oneway constrains cars, not the walker.
  OSM data is © OpenStreetMap contributors (ODbL) and must stay attributed
  in any derivative. Known data gap: PLATEAU tran has **no road
  polygons along the palace east moat (内堀通り, lon ≈ 139.753–139.760 —
  measured: zero carriageway polygons there; 宮内庁-managed roads are not
  open data and the G空間情報センター CKAN has no 皇居/宮内庁 dataset
  either)**, so the default start is パレスホテル前 (丸の内1-1) at the
  data's western edge; the gate side is placed manually on the board.
- `Library/`, `Temp/`, `Logs/`, `UserSettings/` are Unity-generated caches —
  never edit or commit them; they regenerate on open.
