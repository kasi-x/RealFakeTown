# パズル生成アルゴリズム設計 v0.1

> 実在の街（PLATEAU）を盤面に、コンテスト級の「面白い」パズルを安定供給するための生成・検証アルゴリズム。
> 本設計は `docs/game-design.md` §10.8（ソルバQA）・§9（デイリー）・§5（導入カリキュラム）を支える基盤。
> 依存: D8（完全決定論）。提案: D17〜D20（game-design.md §17 に追記済み）。

## 0. 原則（4本）

1. **盤面は実在の街** — 辺は足せない。生成器の動作は「削除（ギャップ／工事中）＋配置（ピース・キャラ）＋予算指定」のみ。削除は事故メタファー／実在工事（§3, §15）として物語に整合する。
2. **面白さの持ち主は挙動（クセ）** — 盤面構造は難しさの上限を決めるだけで、面白さはキャラの挙動が運ぶ。生成は必ず**挙動起点**: どのクセの見せ場を作るかを先に選び、その挙動が必須になるまで盤面を削る。
3. **難度は手数で証明する** — 「N手で解ける／N−1手では解けない」を厳密探索で保証する。詰将棋の手数表記と同じ。
4. **選考はコンテスト型** — 生成器は応募者、審査員スコア（§6）は予備審査、最終選考は人間（ステージデザイナー）。
5. **散歩は必ず終わる（停止性）** — 終端装置は元気ゲージ一つ（0で帰宅）。条件は**累積回復量が有限**なこと（回復系は各1回限り・N回復）。回復を伴わない親切（自律・誘導・声かけ）は繰り返し可。元気を状態に含めたソルバの探索もこれで必ず停止する。

## 1. キャラの操作分類（D20）

将棋の「持ち駒／盤上の駒」アナロジー。ソルバ・生成器・UIの共通語彙。

| 分類 | 位置の決定者 | 動き | 例 | パズル上の役割 |
|---|---|---|---|---|
| **持ち駒**（操作可能） | プレイヤー | 設置・移動・撤去＝1手 | 女子高生・おばちゃん・タクシー・ハチ・マッチョ・警備員 | 手数とKPを消費する能動的な手 |
| **中立キャラ**（場所操作不可能） | 街（スケジュール） | 固定経路・固定時刻で自律移動 | 小学生隊列・犬の散歩マダム・郵便屋さん・ラジオ体操クラブ | プレイヤーは**待ち合わせの幾何と時刻**でしか使えない。時間パズルの主役 |
| **環境**（固定） | 街（不動） | 動かない | 狛犬・バス停・コンビニ・喫茶店・みち案内板・点字つき交差点・点字付き地図・工事中・嘘つきお兄さん・泣いてる子供・駅員さん | 盤面の境界条件。削除・回復・誤誘導・触発・自律イベントの置き場所 |

- 中立キャラの発動は**プレイヤーの手数を消費しない**（世界が勝手に親切する）。N手型では「手数を節約するために街のリズムに乗る」という意思決定を生む。
- 中立キャラの配置（どのアンカーに誰を住まわせるか）は**生成器の変数**。追加は非単調（難度を下げ得る）ので §5-S5 の非単調層で扱う。
- 「盤面のキャラをN手で動かす」変奏（D17）は、中立キャラを例外的に動かせる上級アーキタイプ。物語の被せ方（引っ越し業者が運ぶ等）が別途必要。

## 2. 定式化

- 盤面: 有向グラフ G=(V,E)。直線辺＝WALK、方向ノード＝判断、警告ノード＝HALT。欠損辺＝ギャップ、通行止め辺（toll）＝工事中。
- FSM（§3）: NODE は直進可なら無条件通過（**指示は停止時にのみ参照される**）、HALT と直進不能ノードで指示待ち。優先度ラダーと同距離右回りは完全決定論。
- 盤面追加要素: 一方通行（矢印の向きのみ歩行可——戦略集合を狭める**単調改変**）、行き止まり（進入で即ゲームオーバー）。閉鎖は3段階: ギャップ（永久・削除と同値）／弱い工事（担送で渡れる）／強い工事（仮囲い・**お爺さんだけ**通行不可＝削除と同値、盤面境界に自動設置。子供・犬などのNPCは通り抜けてコースアウト＝画面から自然に消滅）。散歩の終端は元気ゲージ（累積回復量は有限に制限）。
- プレイヤーアクション: (ピース, スロット, 向き, タイミング)。設置・移動・撤去をすべて **1手** と数える（D17）。
- 解: ゴール（駅員さん）到達する手数 ≤ N のアクション列。**最小手数 = ステージの難度**。

## 3. 中核性質（アルゴリズムの土台）

1. **イベント量子化（リアルタイム→ターン化）**: 完全決定論なので、イベント間（ノード到達・停止・時刻イベント）の配置変更は結果を変えない → 探索空間＝イベント木 × 配置状態の有限空間。リアルタイムゲームをターンベースで厳密に解ける。
2. **削除単調性**: 辺削除・toll化は戦略集合を狭めるだけ → 最小手数は**単調非減少**。単調強化（山登り）は後戻り不要。ただし**高原**がある（単一改変で改善しない窪地）→ §5-S4 の多段改変で対処。
3. **手数証明**: 予算 N の全探索は「N−1手で不成立」の証明を兼ねる。生成した全ステージが証明つきで出る。
4. **開始は指示待ち（D18）**: 開始ノードを擬似HALTにする。開始向きという隠れ死因が消え、「最初の一声で歩き出す」チュートリアルに一致。PoC で開始向きが命運を分ける事例を確認済み（§10）。
5. **停止性**: 散歩の終端装置は元気ゲージ（0で帰宅）。回復系の累積を有限（1回限り・N回復）にすれば全軌跡有限で、元気込みのソルバ探索も必ず停止する。PoC では「再獲得できるストック＋ゲージ未実装」で探索が発散することを確認——本番はゲージ込みの状態が正装備。

## 4. 難化ポテンシャル — 「この街でどれだけ難しくできるか」

生成前のマップ分析。地域選定（キャンペーン）とデイリー難度帯の事前評価に使う。

| 指標 | 意味 |
|---|---|
| 経路冗長度 R | 起点集合→駅の単純経路数（対数）。グリッド市街地は高く、幹線+枝路は低い |
| カット余剰 C | k最短経路束上の最小辺カット。削除しても解けなくならない限度 |
| 停止点候補数 | 直進が途切れる／警告になり得るノード数（= 指示待ちアンカー）。**T字路率**: 交差点進入のうち直進辺がない割合。T字への突き当たり進入は必ず停止（基本ルール v2 ①直進の途切れ）＝生成なしの自然難度。路地網の旧市街地は高く、大通り格子は低い。**一方通行で入れない枝は判断の選択肢から除外して数える** |
| スロット密度 S | 判断点近くの歩道アンカー数（§7） |
| もっともらしさ P | 横断歩道の実在しない辺（ギャップの材料）・工事が現実にあり得る辺の割合 |

体感則: **木構造の街は難化しない**（削除が即切断→生成不能か自明）。格子市街地（丸の内想定）は削除候補が豊富で高難度まで強化できる。PoC で再現（§10）。

## 5. 生成パイプライン

```
S1 回廊選択        駅(ゴール)固定 → 開始候補サンプル → k最短経路束で回廊抽出
                  → 基礎可解性ゲート（解けない/自明なら開始・ゴールをリサンプル）
                  → 領域境界に強い工事（仮囲い）を自動設置してコースアウトを防止
S2 候補抽出        削除候補辺（もっともらしさ重みつき、flavor=ギャップ/工事中/一方通行化——いずれも戦略集合を狭める単調改変）・
                  スロット・中立キャラの住まい候補・回復ポイント
S3 挙動選択        ターゲットクセを決める（カリキュラム/難度帯に応じて。例: ハチの右）
S4 単調強化        最小手数がターゲットNに達するまで削除を積む（単一→ペア→ランダムバッチ）。
                  詰みになる改変は禁止、高原は多段改変で脱出（GPUバッチの主戦場）
S5 非単調層        中立キャラ・嘘つき・回復の追加。採用条件は「最小手数が上がる」
                  かつ「ターゲットクセが必須のまま」（受け入れるまでランダム+評価）
S6 認証            厳密最小手数=N を全探索で確定（N−1不成立の証明を兼ねる）。
                  併せて最小解の列挙（解の数）・近傍解（N+1手）の列挙
S7 審査            §6ルーブリックで採点。規定値未満は S4/S5 へ差し戻し
S8 出力            盤面差分（削除+配置）・予算・星/ランク条件・証明（解ログ）付きで
                  エディタへ。人間が最終選考・手直しする
```

- **挙動強制の定式化（S3/S5の判定）**: 「ターゲット挙動 b を禁止した盤面の最小手数 > 予算」なら b は必須。これが「このステージはハチを試すステージ」の1行定義。
- コンボは「1本で1手回復」（D11「親切は返ってくる」の手数翻訳）。星3は「規定手数以上のコンボ解の存在」を S6 の列挙で確認。

## 5.5 難しいパズルの生成アルゴリズム（逆算生成）

「簡単な盤面を難しくする」のではなく、**「解の形を先に設計し、それが唯一の解になるように盤面を逆算する」**。詰将棋の制作手法と同じ発想。

### 逆算生成の5ステップ

```
Step A  技(わざ)の設計
        「この盤面の肝は何か」を1文で決める。
        例: 「子供の連れ帰りで同じ道を2度通る→戻り道で別の出口を選ぶ」
        例: 「嘘つきの角をCOPで通過→その後のルートが開く」

Step B  解のスケッチ
        技が発動する盤面の推移を、ノード列で手描きする。
        例: S → A → B(子供発火,来た道に戻る) → A → C(別の出口) → G
        この時点で「どのノードに何があるべきか」が分かる。

Step C  盤面の構築
        スケッチを満たすように、実グラフから以下を配置する:
        - 技のトリガー（子供・ハチ・看板など）をスケッチの位置に
        - スケッチの経路が通る辺を残す
        - スケッチに含まれない辺を削除（ギャップ・岩・地割れ）

Step D  反実仮想検証
        技を無効化した盤面で解き直す:
        - 技なしで解ける → 技が必須でない → Step C に戻って削除を追加
        - 技なしで解けない → 技が必須 ✓
        さらに: 解の列挙で、技を使わない代替解がないことを確認（唯一解の検証）

Step E  難度の調整
        最小手数がターゲット N に達するまで、以下を追加:
        - 無関係な枝に岩を置く（迂回のコストを上げる）
        - 広場を追加する（停止点を増やす）
        - KPを削る（使えるピースを減らす）
        N-1 手で解けないことを証明して完成。
```

### なぜ逆算が優れているか

| 観点 | 順算（盤面→難しくする） | 逆算（解→盤面を構築） |
|---|---|---|
| 面白さ | 確率的。難しくても面白いとは限らない | 技の見せ場が保証される |
| 計算量 | 全改変候補を探索（組合せ爆発） | 技を軸に絞るので探索が小さい |
| 一意性 | 偶然一意になるのを待つ | ステップDで検証・調整できる |
| デバッグ | 「なぜ難しいか」が不明瞭 | 技の1文で説明できる |

### 実装: 逆算生成器のインターフェース

```
HardPuzzleGenerator.Generate(
    graph: Board,           // 実在街路の手組み盤
    trick: TrickSpec,       // 技の定義（発火条件・期待する解の形）
    start: Node, goal: Node,
    targetMoves: int,       // 目標難度
    maxKp: int              // 予算上限
) → GeneratedPuzzle {
    Board: 変更後の盤面（削除+配置の差分）,
    Solution: 想定解（ノード列+使用ピース）,
    Proof: 反実仮想検証の結果,
    TrickNecessary: bool  // 技が必須であることの証明
}
```

### 技(TrickSpec)の型

```
TrickSpec {
    Mechanic: "child_revisit" / "liar_detour" / "bike_suppress" / ...,
    TriggerNode: Node,       // 発火位置
    ExpectedPath: Node[],    // 想定する解の経路
    FallbackPath: Node[],    // 技を使わない場合の経路（=塞ぐべき経路）
}
```

生成器は FallbackPath を閉鎖（削除・岩・地割れ）して TrickPath だけを残す。Fallback の閉鎖には「もっともらしさ」重みを使い、事故メタファーとして自然な見た目にする。

### 計算量

- Step C の削除: FallbackPath の辺数に比例（線形）
- Step D の反実仮想: ソルバ1回（GPUバッチで並列化可）
- Step E の難度調整: 単調強化ループ（既存の Harden と同じ）
- **全体: 順算の単調強化より計算量が少ない**（削除候補が技の周辺に限定されるため）

### 品質指標

生成後、以下を確認する:
| 指標 | 目標 |
|---|---|
| 技必須性 | 技無効で min > N（反実仮想で証明） |
| 一意解 | 最小解の数 ≤ 許容値（導入=少数、上級=1） |
| 初手の鋭さ | 貪欲ベースラインが失敗する |
| 技の発見可能性 | 盤面を見て技に気づける（矢印・点字・看板の表示） |

## 6. 審査員スコア（コンテスト・ルーブリック）

詰将棋コンテスト（無駄駒・唯一解・初手の鋭さ）とニコリ型パズル募集、IPPデザインコンペの審査基準を計算可能に翻訳したもの。 gates → 加点の2段階。

| 論理 | 項目 | 定義（計算可能） |
|---|---|---|
| gate | 成立 | S6 の証明（N手で解ける） |
| gate | 難度帯 | 目標 N と一致（±0） |
| gate | フェアネス | 使用クセ ⊆ 解放済みカリキュラム。導入済み手のみで初手局面が成立 |
| 加点 | クセの見せ場 | ターゲット挙動が必須（強制判定 OK）。複数挙動の連携が最短解に含まれる |
| 加点 | 無駄のなさ | 全改変・全配置ピースが「除いたら難度が落ちる」こと（leave-one-out）。未使用予算の過大も減点 |
| 加点 | 解の鋭さ | 最小解の数（導入=少数許容、上級=唯一解）。近傍解（N+1手）の数＝にせ筋の豊富さ |
| 加点 | 初手の鋭さ | 貪欲ベースライン（駅方向ヒューリスティック）が失敗する盤面であること |
| 加点 | 中立の見せ場 | 最短解が中立キャラのスケジュールと待ち合わせる（時刻窓の幅も採点） |
| 加点 | 物語 | 削除のもっともらしさ重みの合計。実在ランドマークの利用数 |

重みはステージ種別（チュートリアル/通常/デイリー/週替わり）で差し替える。最終選考は人間が top-K から。

### 技術点（芸術点・D21）

難度（手数N）と**独立**した「解の形」の採点。全検出器が同一パターンで判定できるのが重要:
**反実仮想ソルバ** — その技巧を禁止した盤面で最小手数を解き直し、「最小手数が悪化する（または解けなくなる）＝その技巧が解の要」と証明して加点。反実仮想1回＝ソルバ1回なので §7 のGPUバッチで並列化する。

| 検出器 | 定義 |
|---|---|
| 道の再訪 | 最短解が同じ辺を2度通る。必須性 = 再訪禁止ソルバの最小手数 > N。実装手段が**泣いてる子供**（D22。通ると子供を連れて来た道を戻る） |
| 嘘つきの逆利用 | 最短解が嘘つきの指示に1回だけ従い、その方向が駅遠ざかる方向。嘘つき無効で min > N |
| 再会進行の利用 | 最短解が再会スクリプトの2段目以降（嘘つきの警察突破など）に依存。スクリプトを1段固定すると min > N |
| クセの発動 | ピースのクセ分岐（本業でない枝）が解の要。クセ無効で min > N |
| 貪欲乖離 | 解の手が貪欲ベースライン（駅方向・直進優先）と異なる手の割合 |
| 中立との待ち合わせ | 中立キャラの時刻窓に同期した手（窓幅が狭いほど加点） |

- 週替わりチャレンジ（§9）の「お題」に検出器を直接使える（「今週のお題: 同じ道を二度」= 再訪必須盤面のみ出題）。
- 注意: 再訪は元気を余分に消すため、認証（S6）は元気込みの状態で行う。

## 7. ソルバ実装

- **状態**: (ノード, 向き, 配置状態, 手数残) ＋ 元気・時刻・使用済み/再会カウンタ（触発ピースの再会スクリプト用）・嘘つき学習（本番）。停止イベントごとにアクションを展開し、次イベントまでシミュを一括ロールアウト（メモ化キーに配置状態とカウンタを含む）。
- **探索**: 反復深化 + メモ + (ノード, 元気, 手数) パレート支配。影響圏外スロットの枝刈り。最小手数の確定と解列挙を同じ枠で行う。
- **自律イベント**: 点字つき交差点・点字付き地図は「駅方向矢印（＝最短方向の決定論フィールド）」への従属イベントとして0手展開する。嘘つきは矢印の逆——方向系はすべてこのフィールドとの差分で定義できる（お巡りさんの本業も矢印どおり）。子どもは必ず発火するが移動は上位存在に従う。
- **GPU**: (a) 改変候補のバッチ評価（1候補=1スレッドが部分木を完走、10³〜10⁵並列）が主戦場。(b) 認証の全探索も並列化可能。**認証は常に厳密探索**（NN近似にしない）。
- **計算量の担保**: 到着処理は毎回定数時間（発火順/判断順の線形評価）。**1マス1イベント**（game-design §3）で交互作用ケースを排除し、状態は独立フラグの積に保つ。停止性（元気有限）と有限ストックにより全軌跡有限——探索は必ず停止する。ルール追加は状態フラグの追加で吸収し、交互作用の特殊ケースを作らない。
**計算量の目安**（N=交差点数, E=候補改変数, M=目標手数, G=元気上限, B=バッチサイズ）:

| 処理 | コスト | 備考 |
|---|---|---|
| 到着処理 1回 | O(1) | 発火順/判断順は線形評価。ルール追加も定数係数 |
| 1軌跡のロールアウト | O(G) | 移動1・停止2。元気有限で必ず停止 |
| 最小手数ソルバ 1回 | 到達状態数 × O(G) | 上限は N×4×2^フラグ×配置組合せ(≤M)。メモ化＋パレート支配で実効数千〜10⁵状態（PoC: 7×7・M≤7 でミリ秒〜秒） |
| 強化ルール 1ステップ | 単一 O(E)／ペア O(E²)／ランダムバッチ O(B) | B=10³。GPUの並列単位 |
| 単調強化ループ全体 | O(M × 上記) | 削除の単調性で後戻りなし。高原はペア/バッチで脱出 |
| 認証（N−1不成立の証明） | ソルバの最悪ケース | **最重要のGPU対象**。候補盤面ごとに並列 |
| 解の列挙（一意性・近傍解） | 解数に比例（上限つき打切り） | 冗長な盤面で爆発し得るので必ず上限を設ける |

**v4（発火順/判断順の2層化・1マス1イベント）の影響は定数係数のみ**: 到着処理は線形のまま、交互作用ケース（子供×犬の同時発火など）が構造的に存在しなくなり、状態のクロス項が消えた。指数項は「手数Mに対する配置組合せ」だけで、これは M≤6 の実用域とメモ化・支配で管理する。
- **NN（Phase 2, 任意）**: セルフプレイで手順序ネット（探索高速化）と価値ネット（エディタ上の難易度即時見積り・ヒント機能）を学習。認証とは分離。

## 10. PoC結果（合成 7×7 グリッド、声かけ1種+ギャップ/工事中の縮小模型）

| マップ | 初期min | 強化後min | 改変(gap/toll) | 最小解数 | N+1手解数 | 所要 |
|---|---|---|---|---|---|---|
| 木（+4辺, 到達可能ゴール） | 1 | **1（天井）** | 0/0 | 1 | 0 | <0.1s |
| 格子 12%欠損 | 2 | 6 | 0/1 | 2 | 7 | <0.1s |
| 完全格子 | 2 | 7 | 0/3 | 1 | 1 | 0.2s |

知見（実測）:
- **木は生成できない/難化しない**（削除が即切断、初期盤面が詰む事例も）→ S1リサンプルと地域選定の根拠。
- 完全格子は**単一改変で改善しない高原**があり、ペア/バッチ改変で 2→5→7 と脱出した。GPUバッチの価値を実証。
- toll（工事中）1本で min 2→6 を達成。最小解の数・N+1手解の数が審査指標として安定して計算できる。
- **開始向きが命運を分ける事例**を確認 → 開始指示待ち（D18）の根拠。
- 7×7・N≤8 の厳密求解がCPU単独でミリ秒〜秒。実盤面（数百分ノード・N≤6想定）でもGPUバッチで十分成立する見込み。
- **技術点デモ（泣いてる子供・宣言方向版 D23）**: 通常盤面の最短解に再訪は生じなかった（付随）一方、子供を配置すると再訪が必須化:
  - 完全格子: 子供なし min=7 → 子供@(3,3) 方向(1,0) で min=7 のまま**再訪4辺・再訪禁止=詰み**（再訪必須）。
  - 木の回廊: min=1 のまま再訪4辺が必須。
  - → **難度を上げずに技術点だけを盛れる**（難度と技術は独立軸。D21の実証）。
- **点字付き地図（自律）デモ**: min=6 の盤面で、地図を最短ルートの曲がり角 ((0,6)/(6,0)/(6,1)) に置くと **min=5**——「曲がり角を1つ無料化」する。角以外の配置では不変（自律は判断点でこそ効く）。
- 土地勘ストック（上限1）の数値検証は Phase 1 へ。PoC の発見: 再獲得可能なストック＋ゲージ未実装だと探索が発散する——元気を状態に含めれば自然に停止する（§0 原則5）。
