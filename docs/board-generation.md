# 盤面生成機構（board-generation）

> `docs/concepts/map-mockup.png` 相当の俯瞰平面盤面を、PLATEAU 実データから
> **決定論的に**生成する機構。D33 採用。
> 道路網の土台は既存の歩行グラフ（`tools/gen_city_graph.py`）を流用し、
> ランドマークの「顔」だけを Unity 側で焼き込む。

---

## 0. 採用方式（D33）

盤面のランドマークは、各直線（エッジ）・交差点（ノード）に1棟ずつ代表建物を選び、
**その道路に面する一面（ファサード）を Unity の正射影カメラでトゥーン描画して PNG 化**し、
盤面にカードとして配置する。

**生テクスチャ直接貼りは不採用。** 理由（千代田区2025データで確認済み）:

- LOD2 の壁は**パッチ分割**されている（1メッシュだけで `WallSurfaceTexture` ×802、
  屋根 ×802、付帯物〈看板・空調機等〉がさらに数百枚）。**「1面 = 1テクスチャファイル」
  ではない**ため、生テクスチャを貼ると壁の断片を貼ることになる。
- UV はポリゴンごとの texCoordGen で、きれいな矩形ファサードとして再構築するのは
  Python 側では非現実的。
- 生テクスチャは写実的で、トゥーン＋輪郭線の盤面（§14）と絵柄が衝突する。

**焼き込み方式の利点**: LOD2 の分割・開口部・付帯物をまとめて1枚に解決し、
UV 再構築が不要、ゲームと同じトゥーンシェーダを通すので絵柄が盤面と統一される。

## 1. データの裏付け（Step 0 検証済み）

- 建物 2,548 棟（丸の内コリドー）、**LOD2 98.6%・measuredHeight 100%** →
  フットプリント＋高さは全棟で取れる（`docs/step0-data-verification.md`）。
- `udx/bldg/*.gml` の各建物に `_appearance/` ディレクトリが付属し、壁・屋根の
  JPG テクスチャが実在する（PLATEAU SDK が通常どおり import する）。
- `udx/veg`（植生）・`udx/wtr`（水部）も一式ある → 公園・水辺の描写に使える。

## 2. パイプライン

### S1 ランドマーク選定（Python / `gen_city_graph.py` 拡張 → `landmarks.json`）

- 入力: `udx/bldg` フットプリント（lod0/lod1 ring）＋ measuredHeight ＋ 既存グラフ。
- **エッジごと**: 中心線から半径 20 m 内の建物を候補にする。
- **スコア（D34 私案）**: 「道路に面するファサード長 × 高さ」＝道路から見た存在感。
  footprint 面積は代替案（傾斜ビルや広い低層館の扱いが変わる）。
- **交差点ノードごと**: ノード重心に最も近く、かついずれかの接続エッジに
  面した建物。ファサード方位角は最も近いエッジに対する法線方向。
- **決定性**: 同点は `gml:id` 辞書順。乱数・日時非依存（ソルバ・デイリー盤面の
  再現性要件と同じ）。
- **重複（D34 私案）**: 同一建物が複数のエッジで選ばれるのは「1棟1回」をデフォルト
  （落選エッジは次点に）。`allow_reuse` フラグで許可モードに切替——丸ビル級の
  大型ランドマークが回廊の顔を連続で飾るのを避けるか、逆に使うかの選択。
- 出力 `artifacts/city_graph/landmarks.json`:
  `{ id, kind: edge|node, ref: 要素id, bldg: gml:id, pos: [lon, lat],
     facade_azimuth_deg, height_m, facade_len_m, score, lod, textured, usage }`
- 実装は `gen_city_graph.py` と同じ stdlib-only（ElementTree＋既存の空間グリッド）。

### S2 ファサード焼き込み（Unity エディタスクリプト）

- 各ランドマークについて、ファサード方位角に直交する位置（建物→道路方向）へ
  正射影カメラを配置し、ゲーム本編と同じトゥーンシェーダで RenderTexture に撮影。
- 出力 PNG（512 px 目安）＋メタデータ（gml:id・方位角・バウンディング）。
  保存先 `artifacts/board/landmarks/`（gitignored。生成物の再配布はしない）。
- 角度（D35 私案）: 真正面ではなく**少し傾けた 3/4 俯瞰**（ヨー 30°・ピッチ 30° 目安）。
  真正面は看板のようになり盤面に馴染まない。モックアップの「斜めに置いた建物」
  の文法（§1 Traffic Escape 行）と整合する。
- ラベル（D34 私案）: bldg には基本名が無いので、`urf`（施設）由来の名前があれば
  使い、無ければ `bldg:usage` コードから「事務所ビル／官公庁／商業施設」等の
  種別ラベルを付ける。
- **前提**: PLATEAU import 済みシーンが必要。現状シーン未整備なので
  「GUI import」または「headless import エディタスクリプト」が実験の前段。

### S3 盤面合成

- 地図本体は実データから: `graph.geojson`（道路線・点字ブロック網）＋ tran の
  歩道ポリゴン（歩道リボン）＋ bldg フットプリント（一般建物。§11 のデフォルメ:
  中心ピボット ±10〜15° 交互回転・高さ5段階量子化・トゥーン）＋ `veg`/`wtr`
  （公園・水辺）。
- ランドマークの位置だけ、S2 で焼いたファサードカードを差し込む。
- 出力は2系統:
  1. **SVG/PNG**（`gen_map_mockup.py` 系）— 企画・デバッグ用の確認絵
  2. **Unity 盤面プレハブ** — 本編の盤面（Step 1 以降のブロック網エディタの入力）

## 3. フォールバック連鎖（§4 のクセ記法と同じ 条件→動作→フォールバック）

```
[ランドマーク焼き込み]
条件: 候補建物が LOD2 でテクスチャあり → ファサードを焼く
条件: LOD1／テクスチャ無し       → 単色トゥーンカード（高さ段階で色分け）
条件: 半径内に建物が無い          → 地形カード（veg=公園／wtr=水辺／未整備=汎用緑地）
   ※内堀通り西側の tran データ欠損区間（AGENTS.md 参照）はこのケースに落ちる
```

フォールバック先でも「決定論・同入力なら同出力」を維持する。ランドマークの
役割は「プレイヤーが『あの角だ』と分かる目印」（§16 自分の街感）であり、
フォールバックカードも silhouette としてその役を果たせればよい。

## 5. 検証計画（実験ステップ）

1. **import 前提の整備**: 丸の内コリドー（5次メッシュ選択・基準座標系9系）を
   Unity へ import（GUI または headless エディタスクリプト）。現状シーン未整備。
2. **焼き込み実験**: 適当な棟 5〜10 棟を手指定で S2 スクリプトに通し、
   PNG の見た目（トゥーンの効き方・看板/空調機の映り込み）を確認する。
3. **S1 実装**: `gen_city_graph.py` に bldg 読み＋選定を追加し
   `landmarks.json` を出力（`make graph` に統合）。
4. **S3 合成**: SVG 合成で concept 絵を更新（ランドマークが実データ由来の
   「顔」を持つことを確認）し、盤面プレハブ側の仕様を固める。
